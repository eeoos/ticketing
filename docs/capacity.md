# 트래픽 계산 시트

티켓 오픈 순간 단계별로 몇 명이 몇 건을, 얼마 동안, 초당 몇 건 보내는지 계산한다. 계산은 `scripts/capacity.py`가 하고, 공식은 `tests/test_capacity.py`가 검증한다.

```bash
uv run python scripts/capacity.py   # 아래 결과 표를 다시 출력
```

## 입력값
| 기호 | 값 | 뜻 |
|---|---|---|
| S | 50,000 석 | [가정] 판매 좌석 수 |
| N | 1,000,000 명 | [가정] 오픈 후 T 안에 접속하는 사람 수 |
| T | 60 초 | [가정] 접속이 몰리는 시간(오픈 1분) |
| p | 5 초 | [가정] 대기열 순번 확인(폴링) 간격 |
| μ | 200 명/초 | [가정] 대기열에서 입장시키는 속도 |
| v | 2 회 | [가정] 입장한 사람 1명의 좌석 조회 수 |
| h | 2 회 | [가정] 입장한 사람 1명의 홀드 수 |
| r | 0.4 | [가정] 입장한 사람 중 결제하는 비율 |
| k | 1 회 | [가정] 결제하는 사람 1명의 결제 수(= 좌석 1석) |
| 매진 시 입장 중단 | 예 | [가정·lead 추가] 좌석이 다 팔리면 남은 대기자는 입장하지 않고 폴링을 멈춘다 |
| DB 문장 수 / 요청 | 대기열 진입 0, 순번 확인 0, 좌석 조회 2, 홀드 1, 결제 3 | [가정] 대기열은 DB 밖(메모리·별도 저장소). 나머지는 현재 `backend/main.py`의 성공 경로 기준 |

## 공식
도착률 λ = N / T.

- 입장 인원 A = min(N, ⌈S / (r·k)⌉) — 매진되면 입장을 멈춘다.
- 입장 종료 시각 t_end = A / μ.
- 대기열 최대 길이 Q_peak = N − μ·T (오픈 구간이 끝나는 t = T에서 최대).
- 입장 종료 때 남은 대기자 Q_end = N − A (이들은 매진 안내를 받고 떠난다).
- 대기 인원·초 W = ½·T·Q_peak + (t_end − T)·(Q_peak + Q_end) / 2.
- 이 모델은 **대기열이 생기는 경우**만 다룬다: λ > μ 이고 t_end ≥ T. 아니면 `ValueError`.

| 행 | 사람 수 | 요청 수 | 기간 | 초당 요청 수(피크) | 초당 요청 수(평균) |
|---|---|---|---|---|---|
| 대기열 진입 | N | N | T | N / T | N / T |
| 순번 확인(폴링) | N | W / p | t_end | Q_peak / p | (W / p) / t_end |
| 좌석 조회 | A | v·A | t_end | v·μ | v·μ |
| 홀드 | A | h·A | t_end | h·μ | h·μ |
| 모의 결제 | r·A | r·k·A | t_end | r·k·μ | r·k·μ |
| DB 작업 | — | Σ(행 요청 수 × 그 행의 DB 문장 수) | t_end | Σ(행 피크 × DB 문장 수) | DB 요청 수 / t_end |
| 합계(HTTP) | — | 위 다섯 행 요청 수 합 | t_end | 위 다섯 행 피크 합 (모두 t = T 부근에 겹친다) | HTTP 요청 수 / t_end |

## 결과
`uv run python scripts/capacity.py` 출력(입력값이 모두 [가정]이므로 결과도 추정치). DB 작업 행의 요청 수·초당 수는 SQL 문장 수다.

| 행 | 사람 수 | 요청 수 | 기간(초) | 초당 요청 수(피크) | 초당 요청 수(평균) |
|---|---:|---:|---:|---:|---:|
| 대기열 진입 | 1,000,000 | 1,000,000 | 60 | 16,666.67 | 16,666.67 |
| 순번 확인(폴링) | 1,000,000 | 111,187,500 | 625 | 197,600 | 177,900 |
| 좌석 조회 | 125,000 | 250,000 | 625 | 400 | 400 |
| 홀드 | 125,000 | 250,000 | 625 | 400 | 400 |
| 모의 결제 | 50,000 | 50,000 | 625 | 80 | 80 |
| DB 작업 | — | 900,000 | 625 | 1,440 | 1,440 |
| 합계(HTTP) | — | 112,737,500 | 625 | 215,146.67 | 180,380 |

읽는 법:
- 입장 12만 5천 명(= 5만 석 ÷ 40%)에서 매진되고, 초당 200명씩이라 입장은 625초(약 10분) 걸린다.
- HTTP 요청의 **약 99%가 순번 확인(폴링)**이다. 피크는 오픈 1분 직후 대기자 98만 8천 명이 5초마다 묻는 초당 19만 7,600건.
- 좌석 조회·홀드·결제는 입장 속도(μ)로 묶여 있어 합쳐도 초당 880건이다. DB도 초당 1,440 문장 수준.
- 따라서 처리량을 좌우하는 변수는 폴링 간격 p와 입장 속도 μ다(p를 10초로 늘리면 폴링 요청이 절반).

    admit_rate_per_s=200.0, seat_views_per_user=2, holds_per_user=2,
